## §A. Finish redb parity

### A1. The blocking decision — how a report says "not applicable here"

**Nothing in §A proceeds past A2 until this is settled. It is a judgment call,
not a task.**

Enabling `recall_harness::runner` requires eight APIs veld lacks. Five are real
ports. **Three instrument a directed-edge fix veld does not have** — there is
no `edge_neighbor` and no `dir_fix` branch anywhere in
`src/memory/graph_retrieval.rs`:

- `graph_retrieval::edge_dir_flip_count`
- `graph_memory::directed_reverse_collapse_count`
- `metrics::HUB_SATURATION_EDGE_SKIP_TOTAL`

Adding the accessors makes them return a permanent zero. A report line reading
`EDGE_DIR_FLIPS=0` then says *"the fix ran and flipped nothing"* when the truth
is *"there is no such fix in this build"* — and upstream's identical line means
the first thing. Two projects, one field, two meanings, in reports that exist
to be compared.

Three defensible answers, pick one and write it down:

1. **Omit the field** when inapplicable, and have the diff tool render a
   missing key as `n/a` rather than `0`.
2. **Make the type honest** — `Option<u64>` in the report struct, `null` in the
   JSON, so the absence survives serialisation.
3. **Port the fix itself**, at which point the counter is real. Largest scope;
   only worth it if the directed-edge fix is wanted in veld on its own merits.

(2) is the smallest change that cannot be misread, and it is a schema change to
a format shared with upstream — worth raising there before landing.

### A6. Backup parity — a decision, not a task

**Blocked by:** nothing; touches only `backup.rs` and the five refusals.

Five backup *operations* still refuse by name on redb (`create`, `list`,
`verify`, `purge`, `restore`). That is correct today: the comprehensive backup
is a rocksdb `BackupEngine` facility and redb's route is export/import.

Two honest answers:

- **Widen `BackupStore`** so the comprehensive call is expressible on both, with
  redb's built on export/import.
- **Declare the asymmetry** and surface it at `/health`.

**Never** substitute `BackupStore::create_backup`. It is 4/4 on redb and *not*
comprehensive — no secondary stores, no intent log — so the swap makes the gate
pass and silently downgrades the archive. That is `4d1ec01` returning under a
new name.

What is not defensible is the five refusals quietly persisting once redb is the
default: an operator whose backups have never run should learn it at boot, not
at restore.

## §B. Attribution: make ownership answerable

### B1. The defect, measured

Twice this session a peer asked "is this file yours?" before landing. Both
times the reliable answer came from the gate banner's ledger line. Both times
the obvious command was wrong:

```
git log --author=Portll -- <paths>     # returns the WHOLE FLEET's work
```

**Every session commits as the same human.** The author column cannot
distinguish sessions, and the gate banner says so in the line above its own
commit list ("the author is the SAME human for every session — read the
attribution line below it, not that column"). Sessions still reach for git
first, because git is the tool that looks like it answers this.

Three compounding facts:

1. **The ledger is the oracle, and it works.** `.claude/store/touches.jsonl`
   (254 KB), written by a PostToolUse hook, hash-chained, verified by
   `bin/touch-chain.mjs`.
2. **No session can query it.** `whoTouched()` exists — `bin/gate-ratchet.mjs`
   line ~301 — but it is a private function inside one gate. Not exported, no
   CLI. Six gates read the ledger; a session asking a direct question cannot.
3. **Fleet names are not stable identifiers.** This one transcript was
   `commitwork-54`, `-fe`, `-6b`, `-c9`, `-3b` and `-f6` across restarts. A
   handoff citing a fleet name addresses a session that may no longer hold it.

### B2. Extract `whoTouched` and give it a CLI

**Blocked by:** nothing. Smallest change with the largest effect.

Move `whoTouched()` from `bin/gate-ratchet.mjs` into `bin/lib/` and add:

```
node bin/who-touched.mjs <path>...        # sessions that touched these paths
node bin/who-touched.mjs --since <sha>
```

Keep the shape the gate already relies on. Note the documented history in
`bin/gate-ratchet-core.mjs:94`: it once had three returns of one shared `none`
object, so an empty result could not say *why* it was empty. Preserve that
distinction — "no record" and "record says nobody" are different answers, and
collapsing them is how a session concludes a file is unowned.

**Verification owed:** run it against a path a peer just landed and confirm it
names them; run it against a path nobody has touched and confirm the answer is
distinguishable from an error.

### B3. Make the ledger's blind spots explicit in its own output

`bin/touch-ledger.mjs` documents two real gaps in its header comments:

- Shell-mediated edits (heredoc, `sed`, `python`, `git apply`) were invisible
  until bash was added to the matcher on 2026-08-23. Anything before that date
  under-reports.
- An early version made `node --test x.test.mjs` claim *ownership* of the file
  it merely ran, recording a co-session as having touched three files it had
  only executed.

Both are fixed, but a reader of today's output cannot see either. **Have the
query tool state its own coverage** — the date from which shell edits are
captured, and that a result is a narrowing rather than a settlement. The
existing note in memory is right: the ledger *narrows* ownership, it never
settles it.

### B4. Cite transcript ids, not fleet names

In handoffs, commit messages and peer messages, cite the transcript id
(`70a89ed2-…`). It is stable for the life of the work; the fleet name is not.
`mcp__substrate__open_session` returns both in `ids` — the transcript id is the
one to quote.

Consider making the gate banner print the transcript id alongside "YOU touched
N", so the line a session copies into a reply is already the durable one.
